# Nafay 3D Style Library — 8 Recreated, Ready-to-Use Prompts

**Source reviewed:** https://nafay3d.com/ (11 November 2026)

**Important:** These are newly written prompts based on the publicly visible style descriptions. They are **not** verbatim extractions of Nafay's email-unlocked prompt text. The site currently shows seven style prompts and one style-cloning prompt.

## Fill these fields first

- `[TOPIC]` — what the video is about
- `[SCRIPT]` — narration or speaking script (write `GENERATE` if needed)
- `[DURATION]` — e.g. 30 seconds
- `[FORMAT]` — 9:16, 16:9 or 1:1
- `[BRAND]` — optional identity, colors and logo

## 01 — Creator Motion Graphics

```text
Create a complete, exportable motion-graphics video about [TOPIC] using [SCRIPT] for a [DURATION] runtime in [FORMAT]. Build the motion graphics in code, not as a slide deck or a series of generated still images. Use a near-black backdrop with subtle film grain and occasional restrained light leaks. Headlines should be enormous, condensed, uppercase sans-serif type with physically convincing word-by-word impact, fast staggered entrances and tight easing. Emphasize the single key word in each beat with a contrasting yellow serif treatment. Add hand-drawn circles, directional arrows, highlighter strokes, tilted browser and phone frames, and smoothly counting green metrics only when they advance the message.

Design a fresh visual beat every 2–4 seconds. Match every spoken phrase to the exact visual it describes. Make cuts and transitions feel intentional; no arbitrary shaking or effects. Add original, unobtrusive whooshes, pops and impact sounds synchronized to on-screen actions. Keep the text legible on a phone, maintain safe margins, and ensure captions never collide with important objects. Provide a beat-by-beat storyboard, complete editable source, an automated render command and an MP4 export with audio. If the script is GENERATE, write a precise, natural script before animating.
```

## 02 — Chalk Talk

```text
Produce a [DURATION] animated educational explanation of [TOPIC] from [SCRIPT] in [FORMAT], entirely as code-driven chalkboard animation. Frame the scene as a long, gently worn dark-green classroom slate bordered by wood, with a narrow tray and subtle chalk residue. All illustrations, diagrams, equations and headings must appear as if drawn by an invisible teacher in purposeful strokes. The lines should be dusty, irregular and slightly broken by the grain of the board rather than smooth digital vectors. Use off-white chalk for the main explanation and restrained colored chalk to distinguish key ideas, arrows and corrections.

Animate the drawing in the same order as the reasoning. Sprinkle light chalk dust during active strokes and leave faint ghosts of previous erasures; never overdo particle effects. Break the script into clear teaching stages with one major idea visible at a time. Provide original soft drawing, tapping and eraser sounds, subtle ambience, mobile-readable lettering, and consistent spatial organization. Render a clean MP4 with synchronized audio; provide editable code and instructions to regenerate with a different topic.
```

## 03 — Clean Tech

```text
Build a polished [DURATION] product or technology explainer about [TOPIC], following [SCRIPT], in [FORMAT]. Use a bright, cool off-white canvas, an extremely subtle drifting dot-grid texture, generous white space, sharp alignment and one restrained electric-blue accent. Animate clear Inter Tight-style typography upward into place with soft staggered easing. Present information as sophisticated white interface cards with soft realistic shadows, rounded corners, small monospaced labels and consistent spacing. Use a compact green completion check only to indicate actual completion states.

Every graphic must clarify the narration: feature comparisons, simple processes, progress, data cards, labels or concise UI demonstrations. Keep motion calm and precise; avoid excessive bounce, generic stock graphics and loud scene transitions. Use a grid-based layout with accessible contrast and safe mobile margins. Include subtle custom interface sounds and a very quiet bed that does not cover narration. Deliver a storyboard, code-generated animation, working render steps and final MP4 with audio. If [SCRIPT] is GENERATE, create a brief accurate explainer first and do not invent product claims.
```

## 04 — Software Walkthrough

```text
Create a [DURATION] code-rendered software tutorial in [FORMAT] demonstrating [TOPIC] according to [SCRIPT]. Build a believable app window on a gentle gradient desktop with realistic browser chrome, interactive-looking controls, panels and readable interface content. Animate a clearly visible cursor with natural movement, hover states, precise clicks and small click ripples. Direct the camera smoothly toward the active interface region while keeping the user oriented. Outline important targets with a thin yellow spotlight edge and show short numbered step callouts as actions occur.

Sequence the tutorial as real user actions: orient, locate, click, show result, verify outcome. Synchronize every visual action to narration and leave enough time for the result to register. Do not fabricate interface features as real if specific app screenshots or product details were supplied; reproduce the provided details faithfully. Make all necessary interface elements directly in code. Add restrained UI sounds, soft background audio, accessible text and pointer contrast. Return editable source, any required assets, reproducible render instructions and an MP4 with audio.
```

## 05 — Data Story

```text
Turn [TOPIC] and [SCRIPT] into a [DURATION] data-story video in [FORMAT]. Use an editorial visual language: very dark ink background, spacious layout, bold Archivo-like headlines, disciplined IBM Plex Mono-style numbers, and warm accents chosen consistently from coral, teal and sand. Build every data graphic programmatically. Bars, trend lines, values and annotations must animate from baseline to their real scale with correct axes and explicit units; never make a decorative chart that misrepresents the numbers.

Make each scene communicate a single claim supported by supplied data. Display the exact source and relevant date clearly whenever a statistic appears; if data is missing, label a visual as illustrative rather than inventing a source. Keep transitions refined and paced to the narration, with number rolls, line traces and annotation reveals that reflect actual relationships. Add minimal, synchronized sound and safe spacing for mobile viewing. Deliver a data/claim verification table, storyboard, editable rendering code and final MP4 with audio.
```

## 06 — Warm Canvas

```text
Edit the supplied talking-head video [FOOTAGE_PATH] into a [DURATION] creator explainer in [FORMAT], using [SCRIPT] or the original speech transcript. Begin with clean full-frame footage and sparse, tastefully timed serif captions. When an explanation needs graphics, transition with a soft swoosh to a warm off-white presentation canvas; shrink the original speaker footage into a polished rounded picture-in-picture window without losing lip-sync. Reveal crisp white content cards with Fraunces-like ink or sky-blue headlines, small Inter-style support text and understated pastel tags.

Preserve the speaker's meaning, natural pacing and authentic expression. Cut genuine pauses and clear mistakes only; do not invent spoken words. Motion should be smooth, restrained and thoughtfully choreographed rather than flashy. Keep facial framing, caption placement, typography and card spacing consistent across scenes. Sync graphics exactly with claims in the audio; ensure speaker volume remains dominant over a quiet score and soft transitions. Return a timestamped edit decision list, editable animation/code assets, render instructions and the finished video with captions and audio.
```

## 07 — Pop Info

```text
Explain [TOPIC] in a [DURATION] playful illustrated infographic video using [SCRIPT] in [FORMAT]. Create the full scene as crisp animated vector graphics rather than a slideshow. Set it in a cozy, simplified environment with mild perspective and muted room colors offset by warm, expressive object colors. Include a small, readable character whose gestures and expression change to match the core idea. Use a teal thought bubble as the primary explanatory device; add an animated numeric counter or dotted journey path only when meaningful. Typography should be round, friendly and Fredoka-like.

Build a distinct beginning, middle and end: introduce the question, show the mechanics visually, reveal the takeaway. Use neat shape morphs, path-following motion and a circular iris wipe at key scene boundaries. Avoid clutter, shaky typography, rapid flashing and irrelevant decorative details. Keep everything legible on a phone, with predictable colors and spatial logic. Add original lightweight cartoon sound cues and a quiet backing track. Provide a clear storyboard, fully editable code and a reproducible MP4 render with sound.
```

## 08 — Clone Any Style from Screenshots

```text
I want to create a NEW code-generated animated video style using 1–3 reference screenshots attached to this conversation. My topic is [TOPIC]; my optional narration is [SCRIPT]; target duration is [DURATION] and format is [FORMAT]. First analyze the references, extracting color palette, typography roles, spacing, shape language, composition, layering, lighting, line treatment, visual rhythm and plausible animation behavior. Distinguish what is directly visible from your inferences. Explain the animation/render pipeline you will use, and propose a small set of reusable scenes or components.

Before producing the full video, build one faithful representative TEST FRAME and show it to me, together with a concise style specification. WAIT for my approval before completing the animation. Once approved, develop original reusable code-driven motion sequences and synchronized sound design that follow the analyzed style while adapting every scene to my content. Do not copy logos, copyrighted artwork or distinctive characters from the reference unless I have rights to use them. Provide organized source code, a reusable style configuration, rendering instructions and an exportable MP4 with audio. Do not claim an unseen animation behavior is confirmed by a still screenshot.
```
