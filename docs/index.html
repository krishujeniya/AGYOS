Anchor: 5-Gate Governance Spine

Anchor is the governing spine of AGYOS. It enforces five explicit gates across every non-trivial development task to eliminate hallucinations, out-of-scope modifications, and speculative code:

Anchor Invariant: Ground before mutating. Never mark a milestone complete without fresh machine test output.

  1. UNDERSTAND: Clarify intent, gather requirements, document deliverables in a Task List.
  2. ANALYZE: AST inspection (anchor-scout), blast radius containment, complexity scoring.
  3. PLAN: Architecture Decision Records (ADR), C4 models, test strategy, and context compaction.
  4. IMPLEMENT: Autonomous TDD Red-Green-Refactor loop. Functions <50 lines, files <800 lines.
  5. VERIFY: Full adversarial verification (bin/agyos verify), test ratchet monotonicity.

Emil Kowalski UI/UX & Motion Engineering Standards

Mandatory engineering standards enforced across all frontend, website, and SaaS generation workflows:

  1. Concentric Border Radii Formula: Nested elements must satisfy R_inner = R_outer - padding to eliminate optical corner clipping.
  2. Animation Decision Framework: 100+ times/day = 0ms (no motion); tens of times/day = 150-200ms; modals/sheets = 250-350ms; never animate keyboard actions.
  3. Compositor-Only Animations: Animate ONLY transform and opacity. No layout thrashing on width/height/margin/padding.
  4. Tactile Micro-Interactions: Active scale press feedback (active:scale-[0.98]) on interactive controls.
  5. Popover Transform Origins: Set transform-origin to the trigger button coordinates, never screen center.
Before After Why
transition: all 0.3s transition: transform 0.15s ease Prevents layout thrashing on geometric reflow properties.
transform: scale(0) transform: scale(0.95); opacity: 0 Physical UI elements do not scale from a dimensionless point.

The 6 Non-Negotiable Gravitas Invariants

  1. Ground Before Mutating: Inspect existing implementations and manifests before writing code.
  2. Stay in Declared Scope: Confine file writes strictly to the active milestone path boundary.
  3. Require Machine Evidence: Never claim completion without executing fresh compiler, linter, or test output.
  4. Avoid Identical Retries: If a command fails twice with the same signature, alter the underlying hypothesis.
  5. Satisfy Contract Gates: Phase transitions must satisfy strict programmatic gate criteria.
  6. State Unverifiable Claims: Explicitly flag subjective or machine-untestable behavior.
