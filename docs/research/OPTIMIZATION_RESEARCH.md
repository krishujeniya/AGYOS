# Principles and papers for optimizing AGYOS

Reviewed: 2026-11-11. Code baseline: `190e8ea`. Implementation scope: [plan](OPTIMIZATION_PLAN.md). Reusable instructions: [optimization prompt](../OPTIMIZATION_PROMPT.md). Executed evidence: [results](../OPTIMIZATION_RESULTS.md).

## Recommendation and evidence boundaries

Prioritize correct budget accounting, serializable tool responses, atomic state changes, trustworthy evaluations, and bounded execution before adding agents or longer prompts. AGYOS already contains a large skill catalog, routing, task contracts, recovery primitives, and security components. Their presence does not establish a complete autonomous execution system.

“Top” here means most useful for this repository's decisions, ranked by relevance, source quality, and testability. It is not a citation-count ranking or a claim of exhaustive coverage. This is a targeted review: primary records/abstracts were checked for all selected papers; relevant full-text evaluation and limitation sections were inspected for the three recent harness/scaling papers. No paper experiments were independently replicated. Older plans are context, not fresh evidence.

Search families included agent-computer interfaces, software repair baselines, agent evaluation, prompt injection, agent-system scaling, context engineering, and harness evolution. Official author pages, arXiv records, MIT, Google SRE, and framework documentation were preferred. Third-party rankings and leaked system prompts were excluded. Application to AGYOS is an engineering inference until a local test or experiment supports it.

## Ranked engineering principles

| Priority | Principle | Source basis | Concrete AGYOS application and acceptance |
|---|---|---|---|
| 1 | Enforce limits in code before work starts | P14; explicit constrained budget design | `state_ledger.py::RunBudgetTracker`: reject invalid increments, account for small USD charges, protect recovery capacity, check monotonic elapsed time. Rejecting a charge must leave counters unchanged. |
| 2 | Check every effect at its actual trust boundary | P14, P07 | `scripts/hooks/authorizer.py`, `docs/HOST_COMPATIBILITY.md`: do not infer authorization from model output or reserve-purpose strings. Full host mediation remains an open acceptance dependency. |
| 3 | Grade final state with executable checks | P06, P12 | Test returned JSON, accounting totals, and graph state after failure. A readable explanation or self-reported completion is insufficient. |
| 4 | Keep the smallest effective execution path | P01, P05; [Anthropic guidance](https://www.anthropic.com/research/building-effective-agents) | Preserve deterministic skill routing; require matched-budget improvement before introducing delegation or a model call for routing. |
| 5 | Keep public tool interfaces explicit and serializable | P04 | `skills_router.py::decide_skill`: return only the documented candidate fields; private cached sets must never reach CLI/MCP JSON. |
| 6 | Treat failed changes as transactions | [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence); local graph reproduction | `DAGTaskGraph.add_task`: validate every parent before publishing new maps. Preserve forward references and reject duplicate task identity. Persistence documentation is a design reference, not proof that AGYOS is durable. |
| 7 | Separate development feedback from evaluation | P03, P11 | Existing frozen routing cases are regression/development fixtures. A future agent-quality experiment needs an untouched test split, fixed budgets, and a prespecified grader. |
| 8 | Make an independent checker inspect the result | P02 | Reviewer receives the diff and acceptance criteria; runs tests independently. Record disagreements and unresolved failures. Reviewer approval is not deployment approval. |
| 9 | Measure the operation users experience | [Google SRE monitoring](https://sre.google/sre-book/monitoring-distributed-systems/) | Measure warm routing p50/p95 separately from catalog load, CLI startup, transport, and model/tool latency. Do not turn a sorting microbenchmark into a whole-system speed claim. |
| 10 | Retrieve context as needed | P08; [Anthropic context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) | Load the selected runbook and required references, not the whole catalog. Maintain file pointers and test evidence in the handoff. |
| 11 | Use observed feedback to choose the next action | P09 | Connect failure evidence to the next hypothesis; preserve the five-gate workflow without repeating approvals already granted for local work. |
| 12 | Bound retries and remember the failure | P10, P13 | `ReflectionMemory`: retain error signatures; stop identical retries. Add timeouts to installed-host probes so verification cannot hang indefinitely. |
| 13 | Evaluate both utility and adversarial failure | P07 | Keep forged-authorization, malformed payload, path confinement, and tampering tests alongside normal success paths. Passing one threat case is not a general safety guarantee. |
| 14 | Define service objectives from measured needs | [Google SRE objectives](https://sre.google/sre-book/service-level-objectives/) | Establish a local baseline before choosing latency/error targets. Report cost per successful task and repeated-trial reliability for later model-backed evaluations. Do not invent a production SLO. |
| 15 | Keep dependency, privacy, and provenance claims narrow | P14; repository security specifications | `requirements.txt` has version ranges, not a reproducible environment lock. Model registry metadata and provider prices need separate live checks before operational use. Vault tests do not prove system-wide end-to-end encryption. |
| 16 | Make every optimization reversible and reviewable | P03, P12; local test ratchet | Small diffs, unchanged existing assertions, exact commands, source hashes, raw measurements, documented tradeoffs, and a next step. Reject variants without supported gains. |

These principles apply to similar projects: coding-agent runtimes (SWE-agent), bounded repair pipelines (Agentless), stateful workflow engines (LangGraph), and agent evaluation environments (AgentDojo and tau-bench). Borrow their relevant mechanisms; importing their complete frameworks is not justified by this review.

## Selected papers and their transfer limits

The ordering is implementation relevance, not scientific prestige. “Record verified” means title, authors/year, and identifier were checked against a primary source. arXiv registration is not evidence of peer review. Bibliographic metadata can change between versions; the version links below pin this review.

| ID | Paper, authors, year, primary record | Method and useful finding | Limitation and AGYOS experiment |
|---|---|---|---|
| P01 | **Towards a Science of Scaling Agent Systems**, Yubin Kim et al., 2025/2026, [arXiv:2512.08296v3](https://arxiv.org/abs/2512.08296v3), [full text](https://arxiv.org/html/2512.08296v3) | Controlled comparison of 260 configurations, six benchmarks, and five architectures. Architecture effectiveness depends on task structure; more agents can hurt sequential tasks. | Cross-domain absolute prediction is limited; preliminary scaling only reaches nine agents. Do not hard-code a universal saturation threshold. Compare single-agent and bounded delegation at equal cost on AGYOS tasks. The Nature record referenced in the older plan could not be fetched in this run; its publication claim is not re-certified here. |
| P02 | **Rethinking Verification in Agent Harnesses**, Zhengxin Zhang et al., 2026, [arXiv:2610.34577v1](https://arxiv.org/abs/2610.34577v1), [full text](https://arxiv.org/html/2610.34577v1) | Compares 17 verification designs across seven coding models using Terminal-Bench, SWE-bench Verified, and visual review. Independent critique offers a useful accuracy/cost tradeoff in the evaluated settings. | Recent preprint; the record marks DOI registration pending. Findings do not certify any particular checker. For AGYOS, seed known defects and measure checker false acceptance and added cost. |
| P03 | **Rethinking the Evaluation of Harness Evolution for Agents**, Yike Wang et al., 2026, [arXiv:2607.12227v4](https://arxiv.org/abs/2607.12227v4), [full text](https://arxiv.org/html/2607.12227v4) | Compares harness search with simpler inference-time search at matched budgets. Terminal-Bench 2.1 generalization experiment separates 45 training, 10 validation, and 34 held-out tasks. Game tasks show different outcomes. | Benchmark-dependent preprint results; neither “self-improvement always works” nor “never works” follows. Keep this prompt fixed during final evaluation and report all attempted variants. |
| P04 | **SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering**, John Yang et al., 2024, [arXiv:2405.15793v3](https://arxiv.org/abs/2405.15793v3) | Evaluates purpose-built repository navigation/editing interfaces on SWE-bench and HumanEvalFix. Tool-interface design affects agent behavior. | Model, task, and interface choices differ from AGYOS. Our direct application is a JSON contract regression across Python, CLI, and MCP, not a borrowed task-success percentage. |
| P05 | **Agentless: Demystifying LLM-based Software Engineering Agents**, Chunqiu Steven Xia, Yinlin Deng, Soren Dunn, Lingming Zhang, 2024, [arXiv:2407.01489v2](https://arxiv.org/abs/2407.01489v2) | Uses localization, repair, and validation on SWE-bench Lite; demonstrates that a simple pipeline can be a strong baseline. Also examines problematic benchmark issues. | Historical models and a bounded repair task; not evidence that all business workflows should be agentless. Compare AGYOS's deterministic path with a delegated path before adding coordination. |
| P06 | **tau-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains**, Shunyu Yao, Noah Shinn, Pedram Razavi, Karthik Narasimhan, 2024, [arXiv:2406.12045v1](https://arxiv.org/abs/2406.12045v1) | Simulates user/tool interactions with policy constraints; grades final database state and repeated-trial consistency through pass^k. | Simulated users and particular domains differ from actual customers. Test mocked-tool final states locally; future live/model evaluation must distinguish pass@k from pass^k. |
| P07 | **AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents**, Edoardo Debenedetti et al., 2024, [arXiv:2406.13352v3](https://arxiv.org/abs/2406.13352v3) | An extensible environment of 97 tasks and 629 security cases evaluates agents consuming untrusted tool data. Measures useful completion and attack outcomes. | Finite attacks do not prove universal defense; attacks and defenses evolve. Expand AGYOS mocked adversarial fixtures without treating retrieved instructions as authority. |
| P08 | **Lost in the Middle: How Language Models Use Long Contexts**, Nelson F. Liu et al., 2023, [arXiv:2307.03172v3](https://arxiv.org/abs/2307.03172v3) | Multi-document QA and key-value retrieval show sensitivity to where relevant information occurs in context. | Older models and retrieval tasks; no universal optimal context length follows. Measure selected-runbook context against bulk catalog injection on held-out tasks. |
| P09 | **ReAct: Synergizing Reasoning and Acting in Language Models**, Shunyu Yao et al., 2022/2023, [arXiv:2210.03629v3](https://arxiv.org/abs/2210.03629v3) | Interleaves planning with actions and observations across language and interactive tasks. | Does not establish authorization, transactional recovery, or secure tool execution. Record concise action/evidence summaries and grade resulting state; no private reasoning transcript is required. |
| P10 | **Reflexion: Language Agents with Verbal Reinforcement Learning**, Noah Shinn et al., 2023, [arXiv:2303.11366v4](https://arxiv.org/abs/2303.11366v4) | Uses feedback and episodic textual memory across reasoning, coding, and sequential decision tasks without changing model weights. | Self-generated feedback can be wrong. Compare one evidence-based retry with one blind retry; retain external test evidence and a strict retry cap. |
| P11 | **DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines**, Omar Khattab et al., 2023, [arXiv:2310.03714](https://arxiv.org/abs/2310.03714) | Expresses language-model pipelines as modules and optimizes them against an explicit metric in multiple task settings. | Metric quality and evaluation separation determine usefulness. Adopt explicit objectives and held-out grading; no DSPy dependency or automatic model spending is needed for this patch. |
| P12 | **SWE-bench: Can Language Models Resolve Real-World GitHub Issues?**, Carlos E. Jimenez et al., 2023/2024, [arXiv:2310.06770v3](https://arxiv.org/abs/2310.06770v3) | Introduces 2,294 issues across 12 Python repositories, requiring repository edits assessed in an execution environment. | Historical benchmark distribution is not AGYOS production acceptance. Reproduce defects before repair and preserve existing test assertions. |
| P13 | **Why Do Multi-Agent LLM Systems Fail?**, Mert Cemri et al., 2025, [arXiv:2503.13657v3](https://arxiv.org/abs/2503.13657v3) | MAST analyzes 1,600+ annotated traces from seven frameworks and groups 14 failure modes into design, alignment, and verification categories. | Taxonomy is diagnostic, not a predictive guarantee or universal failure rate. Tag AGYOS failures by contract, routing, budget, dependency, verification, and recovery. |
| P14 | **The Protection of Information in Computer Systems**, Jerome H. Saltzer and Michael D. Schroeder, 1975, [author-hosted paper](https://web.mit.edu/Saltzer/www/publications/protection/), [principles section](https://web.mit.edu/Saltzer/www/publications/protection/Basic.html) | Foundational design argument for least privilege, default denial, complete mediation, and simple mechanisms. | Architectural reasoning, not an LLM experiment. Inspect all actual effect paths and invalid inputs. A purpose label, cached approval, or successful smoke test cannot establish trusted authorization. |

## Follow-up experiments, with acceptance criteria

1. **Host mediation (security/runtime owner; first dependency):** disposable workspace, pinned host, harmless tool denial/failure/cancellation probes. Acceptance: every tested effect reaches trusted policy enforcement; record unsupported paths. A model-backed probe requires separate cost authorization.
2. **Real task quality (evaluation owner; after host contract):** stratify coding, research, safe workflow, and adversarial tasks; separate development/validation/test sets by task family; compare baseline prompt and this prompt at identical model/tool/token/time budgets. Report final-state success, pass^3, forbidden actions, cost per success, and confidence intervals. No claimed improvement without this run.
3. **Context experiment (runtime/evaluation owners):** fixed task set and model; vary only context retrieval strategy, measure tokens and success. Keep runbook references traceable and test catalog freshness for a long-lived server.
4. **Durability and concurrency (runtime owner):** explicit dispatch integration, reservation/settlement, persistent idempotency, crash-replay and cancellation tests. Current trackers are single-owner primitives; do not share them across workers as a concurrency control.
5. **Reproducible dependencies and supply chain (maintenance owner):** lock a supported environment, validate on CI's Python version and the local version, run a redacted secret scan and dependency audit, review transitive license notices. Do not mass-upgrade the catalog's embedded examples.

The master prompt encodes these principles, but a prompt cannot make AGYOS globally optimal or enforce controls that the host does not implement.
