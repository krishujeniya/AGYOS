  settle a content debate with evidence instead of opinion. Designs disciplined organic tests: one

  controlled sequential posts (exception: YouTube's native Test & Compare); the result is read from
  native analytics via analytics-and-reporting. Organic can't reach true statistical significance;
  nothing is fabricated or p-hacked. Distinct from analytics-and-reporting (measures) and
  goals-and-kpis (sets targets).

This skill **designs** the test and drafts variants; **scheduling-and-queue → WoopSocial**\npublishes them; **analytics-and-reporting** reads the result.\n\n"
  - "## The POV: evidence, not vibes\nMost \"testing\" on social is vibes — post two things, eyeball the likes, declare a winner, learn nothing.\nReal experimentation turns guesses into evidence: change **one variable**, control everything else, set\nthe **decision rule before you publish**, and run it **long and often enough** to separate signal from\nnoise. Organic can't give clean statistical significance (small samples, an algorithm in the middle), so\nyou compensate with tighter controls, a **~20%+ effect threshold**, **guardrail metrics**, and **3–5\nrepetitions** — and treat a single viral post as **noise, not a strategy.**\n\n"
  - "## Read these first\n1. **brand-profile** — voice/format constraints for the variants.\n2. **goals-and-kpis** — the **KPI/primary metric** the test must move.\n\n"
  - "## The framework: TEST\n(Depth: `references/the-test-framework.md`.)\n- **T — Target one variable:** a clear hypothesis; change ONE element (hook/first-frame/caption/CTA/time/\n  format), everything else identical; pick the highest-leverage one.\n- **E — Establish the decision rule first:** set the **primary metric + win threshold + guardrail** before\n  publishing (\"B wins if reach +15% and saves/reach not worse\"); no post-hoc rationalizing.\n- **S — Set controls + sample:** same platform/format/topic/length/window; run ≥7 days (small accounts\n  2–4 weeks); judge on a **~20%+ consistent effect** (a tie = \"test elsewhere\").\n- **T — Tally, repeat, scale:** **3–5 paired repetitions** before a \"best practice\"; log every test;\n  scale winners into the playbook (`content-recycling`), retire the rest.\n\n"
  - "## What to test (highest leverage, in your control)\nHook/first-frame (short video) → posting time (easy) → format → caption/CTA → thumbnail → hashtags —\nalways tied to the KPI; test what's **in your control**, not algorithm-dependent factors. Run a **30-day\nsprint** with one test always running. Priority list, design template, sprint plan, testing log + worked\nexamples: `references/what-to-test-and-recipes.md`. Full method + rules:\n`references/experimentation-2026-reality.md`.\n\n"

(verify-quarterly)\n- **No p-hacking / HARKing / cherry-picking** — decision rule pre-set; a multi-variable change can't be\n  pinned on one element; one post/one day is noise. **Never fabricate a result; a tie is valid.**\n  (Scope, the loop role + connections: `references/scope-and-connections.md`.)\n\n"
